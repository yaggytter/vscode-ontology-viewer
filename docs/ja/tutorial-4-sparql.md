# チュートリアル4: SPARQL で問い合わせる

SPARQL は RDF のための問い合わせ言語です。まだ一行も書いたことがなくても、このチュートリアルなら1分ほどで実際の答えが得られます。パネルには実行可能なサンプルが用意されているので、**書くことから始めるのではなく、動かすことから始められます**。

ここでは **Harbor Market（港の朝市）** を使います。クラス（Stall や Product）というスキーマと、探す対象になる実際のインスタンスの両方が含まれているサンプルです。**「Ontology Viewer: サンプルオントロジーを作成...」** を実行して **Harbor Market** を選び、`Cmd+Alt+O` / `Ctrl+Alt+O` で図を開いてください。

## 1. SPARQL パネルを開く

図のツールバーにある **SPARQL** をクリックします。キャンバスの上にパネルが開き、サンプル選択、クエリ入力欄、結果表示領域が現れます。

## 2. 何も書かずに最初のクエリを実行する

**サンプル:** から **「1. とにかく何か表示する（最初の20トリプル）」** を選びます。入力欄が次のように埋まります。

```sparql
SELECT ?subject ?predicate ?object
WHERE {
  ?subject ?predicate ?object .
}
LIMIT 20
```

**実行** を押します（`Ctrl`/`Cmd`+`Enter` でも実行できます）。20行の表が返ってきます。

これが SPARQL クエリの基本形です。`SELECT` で欲しい列を指定し、`WHERE` で探すパターンを書きます。`?subject` は**変数**で、何にでも一致し、一致した内容がその列に表示されます。ここでは「どんな文でもよい」というパターンなので、すべてが返ってきます。

## 3. 目的を絞って問い合わせる

**「2. すべてのクラスを一覧する」** を選びます。

```sparql
SELECT ?class ?label
WHERE {
  ?class a owl:Class .
  OPTIONAL { ?class rdfs:label ?label }
}
```

新しい考え方が2つあります。

- `a` は「〜である」（`rdf:type`）の省略記法です。`?class a owl:Class` は「クラスとして宣言されているものを探す」という意味になります。
- `OPTIONAL` は**ラベルがあれば含める**という指定です。これがないと、ラベルを持たないクラスは結果から完全に消えてしまいます。

Vendor、Stall、Product、Market Day が表示されるはずです。

## 4. 図が反応するのを見る

図の中でクエリを実行できることの価値が出るのはここです。**一致時:** の選択が **ハイライト** になっていることを確認してください。

**「3. インスタンスとそのクラスを一覧する」** を選んで実行します。結果には Pier Stall や Sea Salt Crackers といった個体が並び、図では一致したノードにハイライトのリングが付きます。

既定の **スキーマ** ビューでは、個体そのものではなく **Stall** と **Product** がハイライトされます。これは意図した挙動です。スキーマビューはインスタンスではなくクラスを描画するため、`:pierStall` への一致は、それが属するクラスを光らせます。**トリプル** ビューに切り替えて同じクエリを実行すると、今度は `pierStall` と `seaSaltCrackers` の個体ノードが直接ハイライトされます。そのビューが実際にそれらを描画しているからです。

残り2つのグラフモードも試してみてください。

- **絞り込み** は、クエリに一致しなかったものを淡色化します。答えだけが明るく残ります。検索ボックスやダブルクリックのフォーカスと組み合わせられるので、クエリと名前の両方で同時に絞り込めます。
- **グラフに反映しない** は図をそのままにして、テキストの結果だけを表示します。

## 5. 件数を数える

**「4. クラスごとにインスタンス数を数える」** を選びます。

```sparql
SELECT ?class (COUNT(?instance) AS ?instances)
WHERE {
  ?instance a ?class .
}
GROUP BY ?class
ORDER BY DESC(?instances)
```

`GROUP BY` は同じクラスを持つ行をひとつにまとめ、`COUNT` はまとめられた件数を数え、`AS ?instances` はその結果の列に名前を付けます。`ORDER BY DESC(...)` で大きい数を先頭にします。

## 6. 文字列を検索する

**「7. ラベルを単語で検索する」** を選びます。

```sparql
SELECT ?resource ?label
WHERE {
  ?resource rdfs:label ?label .
  FILTER(CONTAINS(LCASE(STR(?label)), "a"))
}
```

`FILTER` は条件を満たさない行を捨てます。`STR` はラベルを素のテキストに変換し、`LCASE` は小文字化して大文字小文字を区別しないようにし、`CONTAINS` が部分一致を判定します。`"a"` の部分は好きな単語に置き換えられます。`"stall"` などを試してみてください。

## 7. はい／いいえの質問と、生成されるグラフ

表以外のものを返すクエリ形式が2つあります。

- **「8. はい／いいえで問い合わせる」** は `ASK` を使い、`true` か `false` を返します。行はなく、ハイライトするものもありません。
- **「9. リソースだけのグラフを構築する」** は `CONSTRUCT` を使い、表ではなく**トリプル**を返します。結果領域には主語・述語・目的語の行として表示されます。この例はリソース間のつながりだけを残してリテラル値を除外するので、文字列や数値のノイズを除いたグラフの形を素早く把握できます。

## 自分でクエリを書く

自分のオントロジーには固有の名前空間があるので、プレフィックスを宣言します。Harbor Market の場合は `https://example.org/ontology/harbor-market#` です。

```sparql
PREFIX : <https://example.org/ontology/harbor-market#>
PREFIX rdfs: <http://www.w3.org/2000/01/rdf-schema#>

SELECT ?stall ?product
WHERE {
  ?stall a :Stall ;
         :offers ?product .
}
```

`;` は直前の主語を繰り返す記法です。つまりこれは「Stall を探し、その同じ Stall が提供している商品を探す」と読めます。

知っておくと便利な点があります。ハイライトさせたいリソースを、**結果として返す必要はありません**。次のクエリはリテラルしか返しませんが——

```sparql
SELECT ?stallLabel ?price
WHERE {
  ?stall a :Stall ; rdfs:label ?stallLabel ; :offers ?product .
  ?product :unitPrice ?price .
}
```

——それでも図では Stall と Product がハイライトされます。返されたリテラルは、それを持つリソースへ遡って解決されるため、どの列を射影したかではなく、そのクエリが**何についてのものか**が図に反映されます。

## 補足

- **SELECT、ASK、CONSTRUCT、DESCRIBE** に対応しています（SPARQL 1.1）。
- クエリは、保存していない編集内容も含め、エディタの**現在の内容**に対して実行されます。
- すべて VS Code 内で**ローカルに**実行されます。オントロジーの内容が外部に送信されることはありません。
- 構文エラーや失敗したクエリはパネルに表示され、図はそのまま保たれます。
