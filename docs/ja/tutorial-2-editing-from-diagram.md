# チュートリアル2: 図から編集する

この機能こそが、本拡張機能を単なるビューアと分ける核心部分です。図の中でクラス・関係・プロパティを新規作成したり、既存のものをリネーム・型変更したりすると、それがファイルに書き戻されます。

## 「編集可能」とはどういう意味か

ノードが**点線の枠**で表示され、Inspector 上のフィールドが操作可能になっているのが「編集可能」の目印です。これは、その `rdfs:label`（プロパティの場合は宣言自体）を対象エンティティへ安全に書き戻せる場合を意味します。通常のフラットな Turtle ファイルであれば、ほとんどの場合これに該当します。**該当しない**のは:

- 既存の `rdfs:label` が複数行（三重引用符）の文字列である場合
- 空白ノードのプロパティリスト（`[ ... ]`）や RDF コレクション（`( ... )`）の中にネストしてしか登場しないエンティティ
- provenance が `declared`（宣言由来）ではなく `inferred`（推測）であるプロパティ — 使用状況から図が推測しただけで、ファイル内に編集対象となる宣言がまだ存在しない場合

これらは意図的に設けた制限です。理由は [対応形式](format-support.md) をご覧ください。

## エンティティをリネームする

1. （**「Ontology Viewer: サンプルオントロジーを作成...」** から）`samples/neighborhood-garden.ttl` を開き、図を表示します（既定でスキーマビューが開きます）。
2. **Riverside Garden** ノードをクリックします。右側に Inspector が開き、名前欄に `Riverside Garden` と表示されます。
3. 名前欄をクリアして `Riverside Community Garden` と入力し、Enter を押す（またはフォーカスを外す）と確定します。
4. テキストエディタを見てみましょう。以下の行が

   ```turtle
   :riversideGarden a :Garden ; rdfs:label "Riverside Garden"@en ; :containsPlot :sunnyPlot .
   ```

   次のように変わります。

   ```turtle
   :riversideGarden a :Garden ; rdfs:label "Riverside Community Garden"@en ; :containsPlot :sunnyPlot .
   ```

   ファイルの他の部分は一切変わりません。再整形もされず、プレフィックスの順番もコメントもそのままです。

## プロパティを追加する

Inspector の「プロパティ」一覧の各行には名前欄と型のドロップダウンがあり、一覧の下に **+ Property** ボタンがあります。

1. **Plot** ノードをクリックします。
2. **+ Property** をクリックし、`wateringFrequency` と入力して確定します。
3. ファイルの末尾に新しい文が追加されます。

   ```turtle
   :wateringFrequency a owl:DatatypeProperty ;
     rdfs:label "wateringFrequency" ;
     rdfs:domain :Plot ;
     rdfs:range xsd:string .
   ```

4. Inspector に戻り、ドロップダウンから型を変更（例: `integer`）すると、`rdfs:range` がその場で `xsd:integer` に書き換わります。

## クラスを追加し、関係で別のクラスとつなぐ

1. ツールバーの **+ Class** をクリックし、名前（例: `Compost`）を入力して確定します。新しい `owl:Class` ノードが表示され、自動的に選択状態になります。
2. ツールバーの **Connect** をクリックし、次に起点となる **Plot** ノード、続いて新しく作った **Compost** ノードの順にクリックします。関係の名前を尋ねられるので、`receivesCompost` などと入力します。
3. `rdfs:domain :Plot` と `rdfs:range :Compost` を持つ新しい `owl:ObjectProperty` が追記されます。2回目のクリックの前であれば **Esc** キーでいつでもキャンセルできます。

## 安全性: 検証に失敗したらどうなるか

図からの編集も F2 によるリネームも、ファイルに触れる前に必ず同じ手順を踏みます。

1. 編集後のテキストがどうなるかを計算する。
2. その提案されたテキストを最初から再パースする。
3. 結果として得られるグラフが、意図した変更とちょうど一致していることを確認する。
4. ここまで通ったときだけ、実際のドキュメントに適用する。

3 の確認に失敗した場合、編集は破棄され、トーストでエラーメッセージが表示されます。ファイルには一切手が加わりません。これは意図的な設計です — 想定外のケースでデータを黙って壊してしまうツールは、実務で使うには危険すぎます。

## ラベルではなく識別子（IRI）自体をリネームする

Inspector の名前欄の編集では、エンティティの `rdfs:label` が変わるだけで、IRI／ローカル名そのものは変わりません。識別子自体を（例えば `:riversideGarden` → `:riversideCommunityGarden` のように）使われているすべての箇所でリネームしたい場合は、テキストエディタでカーソルをその上に置き、**F2**（シンボルの名前変更）を押してください。こちらも同じ安全性チェックを経てからリネームが提案されます。

## プロパティや関係を削除する

Inspector の宣言由来のプロパティ行には小さな 🗑 ボタンが、選択中の宣言由来の関係（`owl:ObjectProperty` — `subClassOf`/`skosBroader` の辺は対象外）には専用の **Delete** ボタンがあります。削除すると、そのプロパティ／関係の宣言全体（`;` でつながったすべての文）が1つの単位としてまとめて消え、ファイルの他の部分には触れません。

そのプロパティ／関係がファイル内の他の場所でまだ使われている場合（述語として使われている、例: `:lemonBalm :growsIn :sunnyPlot`、あるいは `owl:inverseOf` などから参照されている場合）は、削除前に確認ダイアログが表示され、削除するとどれだけの箇所が存在しないものを指すことになるかを教えてくれます。

削除が拒否される場合（トーストが表示され、テキストエディタが該当する宣言にジャンプするので、そこから手動で完了できます）:

- 宣言が単純な形式ではない場合（入れ子の `[ ... ]`/`( ... )` や複数行リテラルを含む — 他の書き戻し操作と同じ基準）
- 同じ主語がファイル内で複数の別々のトップレベル文として宣言されている場合（まれですが、この拡張機能はどちらを削除すべきか推測しません）

## 図からまだできないこと

**クラス**の削除や、`subClassOf`/`skosBroader` の**辺**の削除はまだ実装されていません。例えば Inspector の説明欄を空にしようとすると、テキストを黙って破棄するのではなく「未対応」であることを説明するトーストが表示されます。クラスの宣言は通常ファイル内の他の多くの場所から参照されており（ドメイン/レンジとして使うすべてのプロパティ、すべてのサブクラス、すべての個体など）、安全に削除するにはプロパティや関係の単純で自己完結した宣言よりもずっと大掛かりな参照チェックが必要です。今のところは、テキストエディタで該当行を直接削除してください。保存すれば図に反映されます。
