# トラブルシューティング

## 図が空のまま

- 問題パネル（Problems）を確認してください。ファイルに構文エラーがある場合、図は直前の正常な状態を表示し続けます（一度も正常にパースできていない場合は何も表示されません）。
- `rdf:type` やクラス・プロパティ・個体のトリプルが一つもないオントロジーは、設計上、空の図になります。まだ描くものがないだけです。

## SPARQL クエリで結果は返るのに図が変わらない

まず SPARQL パネルの **一致時:** の選択を確認してください。**グラフに反映しない** になっている場合は、設計どおりテキストのみの結果になります。

それ以外で最も多い原因は、現在のビューが描画していないものに一致しているケースです。**スキーマ** ビューはクラスを描画し、**トリプル** ビューはすべてのリソースを描画します。そのため、個体に一致したクエリは、スキーマビューではその**クラス**を、トリプルビューでは個体自身をハイライトします。スキーマビューで何も光らない場合は、**トリプル** に切り替えて再実行してみてください。

なお、ハイライトさせたいリソースを結果として返す必要は**ありません**。ラベルや価格、名称といったリテラルしか射影していないクエリでも、それらのリテラルを持つリソースがハイライトされます。行が返っているのに、どちらのビューでも何もハイライトされない場合は、Issue でご報告ください。

`ASK` クエリは何もハイライトしません。`true`/`false` を答えるだけで、指し示すリソースが存在しないためです。

## SPARQL クエリが失敗する・結果が0件になる

- 構文エラーはパネルに表示され、図はそのまま保たれます。`PREFIX` の宣言漏れ、`{` の対応漏れ、最後のパターン末尾の `.` などを確認してください。
- 0件という結果自体は正しい答えです。まず組み込みの **サンプル:** を実行してその文書でパネルが動くことを確認し、そこから絞り込んでください。
- 自分の名前空間には `PREFIX` の宣言が必要です。サンプルが宣言しているのは `rdf:`・`rdfs:`・`owl:` だけなので、自分のオントロジーの用語を使うパターンには独自の `PREFIX` 行が必要です。
- クエリは、保存していない変更も含め、エディタの現在の内容に対して実行されます。

順を追った解説は [SPARQL チュートリアル](tutorial-4-sparql.md) にあります。

## ノードに点線の枠がなく編集できない

そのエンティティのラベルは、現時点では図から安全に編集できません。よくある理由:

- 既存の `rdfs:label` が複数行（三重引用符）の文字列である
- 空白ノードのプロパティリスト（`[ ... ]`）や RDF コレクション（`( ... )`）の中にしか登場しない

全リストは [対応形式](format-support.md#turtle-の中でも制限がある部分) をご覧ください。テキストエディタで直接編集してください。

## 編集が反映されない・エラーが出る

本拡張機能は、提案されたすべての編集を書き込む前に再パースし、期待した結果とちょうど一致しない場合は書き込みを拒否します。Inspector のフィールド編集や F2 リネームの後にトーストでエラーが表示された場合、何も書き込まれていません。ファイルは変更されていません。これは意図的な設計です — 推測して誤った内容を書き込みオントロジーを壊してしまうより、編集を拒否するほうが安全です。一見普通の Turtle に見えるファイルでこれが起きた場合は、最小限の再現手順を添えて Issue を報告してください。

## `Cmd+Shift+O` / `Ctrl+Shift+O` で図が開かない

想定通りの挙動です。これは VS Code 標準の「シンボルへ移動（Go to Symbol in Editor）」です。本拡張機能は代わりに `Cmd+Alt+O` / `Ctrl+Alt+O` を使います。大きなオントロジーファイルほど本当に便利なショートカットを奪わないためです。新しいショートカットを覚えたくない場合は、エディタツールバーのボタンかコマンドパレットをお使いください。

## RDF/XML や JSON-LD ファイルで図から編集できない

これは意図的な設計です。[対応形式](format-support.md#なぜ-turtle-だけが編集可能なのか) をご覧ください。まず **「Ontology Viewer: 編集用に Turtle へ変換...」** を実行してください。

## ノードの位置が消えてしまった

ノードの位置は、オントロジーファイル本体ではなく VS Code のワークスペース状態に、ファイルの場所をキーとして保存されます。既定では他のマシンとは同期されません。別のマシンや別のワークスペースフォルダから同じファイルを開くと、自動配置されたレイアウトから始まります。レイアウトを明示的に保存（共有）したい場合は **「Ontology Viewer: 図のレイアウトを JSON でエクスポート...」** をお使いください。

## それでも解決しない場合

以下を添えて GitHub リポジトリに Issue を立ててください。

- VS Code のバージョン（`Help > About`）
- 拡張機能のバージョン
- 問題を再現できる最小限の `.ttl`／`.owl`／`.jsonld` ファイル
